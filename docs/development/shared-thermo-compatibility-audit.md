# 官方更新与个人补丁的行为兼容性

## 可复现的发现和处置

扩展的第一轮正式 Maven 回归共 215 项，17 项失败，0 错误、0 跳过。
逐项断言和测试类保存在[修复前记录](../../distribution/cupbhan/compatibility-audit/before.json)。
失败数不等于独立根因数，包含恢复逻辑冲突、严格数值路径差异和模型参数差异。

| 代码/行为 | 发现 | 最终处置 |
| --- | --- | --- |
| `TPmultiflash` 相删除与恢复 | 旧的失败保护拦截了官方相集合恢复；干烃、酸气及含水井流可能留下多余相或破坏守恒 | 为非反应、无离子流体恢复官方路径；保留诊断以及外层终态验收；反应及离子体系保留个人保护 |
| `Flash` 稳定性试探前 K 值回存 | 改变了新版稳定性计算的数值路径；官方含水立方根一致性测试失败 | 移除这项旧补丁，采用官方实现，同时复验个人含水与 FieldFluid 回归 |
| `SystemThermo` 相索引重排 | 旧的全相槽排列补丁干扰新版重复调用/酸气结果 | 移除该补丁，采用官方实现；保留别名相槽库存、序列化、反应克隆与组成修改回归 |
| `EosMixingRuleHandler` 水/轻质 TBP 参数 | 个人默认 0.5 与官方默认 0.2 不同，使比较使用了不同模型 | 普通模型恢复官方默认；历史调整由显式 `setLightPseudoWaterCompatibility(true)` 保留 |
| `PhaseEos` 与研究算法的油/水标签 | EOS 用质量贡献，研究算法却以水摩尔分数 0.5 判断，导致同一液体身份矛盾 | 保留个人 EOS 质量约定，抽取 `LiquidPhaseClassification` 供指定相验收和边界算法共同使用 |
| 初生相稳定性/驻点结果标签 | 单凭高水摩尔分数会把水蒸气标成水相；官方系统初始化又会将非零相槽的气根重新标为油 | 使用 EOS 已求值体积/共体积及共享液体分类规则，绕过相槽标签覆盖；增加纯水蒸气回归 |
| `PhaseEos` 混合规则深克隆 | 参数配置需要独立副本，不能向调用者泄漏修改 | 保留并验证副本隔离 |
| 冻结重油资源与显式边界族倍率 | 与默认模型修复是不同的参数合同 | 三份冻结 JSON 的 SHA256 保持不变；倍率继续显式选择 |

历史轻质 TBP 配置只修改非 CPA 的轻质 TBP/水常数交互参数，先应用历史值，再应用所选边界族倍率。
它不会把轻质相关式外推到重质 TBP，也不会覆盖 CPA 关联模型参数；测试检查自定义重质参数和原流体保持不变。
默认值恢复意味着使用默认水/轻质 TBP 流体的旧结果可能变化；需要复现旧模型时必须显式记录该配置。

质量贡献约定是本分支的液体命名规则，并不等价于热力学稳定性判据。
气相身份、物料守恒、逸度一致性、相间距离以及有限 TPD 搜索仍分别验收。

## 对照方法

从上述失败中抽取 9 个关键测试方法，对纯官方 v3.23.0 JAR 和旧个人 3.17.0 运行包做同输入对照：
官方 9 项通过；旧个人版 2 项通过、7 项失败。另用隔离类覆盖逐项撤销或调整旧补丁，
确认恢复逻辑、K 值回存、相槽重排和参数默认值的影响。
这些测试方法的结果和两个对照 JAR 的 SHA256 见[差分记录](../../distribution/cupbhan/compatibility-audit/differential.json)。
反射对照只调用普通 `@Test` 方法，不覆盖参数化用例或完整 JUnit 生命周期，不能计作完整 215 项回归。
最终候选门槛使用正常 Maven/JUnit 执行，并同时保留官方与个人测试。

组合验证还发现：只对无水和 CPA 放开恢复仍会使一个普通 SRK 含水历史用例失败。
最终恢复范围覆盖非反应且无离子的含水体系，该用例维持原有相数、守恒和逸度断言。
相身份测试另外识别了系统层对非零相槽的气相重命名；只读取 `getType()` 不足以验证试探根身份。
